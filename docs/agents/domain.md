# Domain docs

Use a single-context layout:

- `GLOSSARY.md` at the repo root for domain vocabulary.
- `docs/adr/` for architectural decisions shared across the application.

Before exploring an area, read the glossary and relevant ADRs. If these files do not exist, proceed without creating placeholders. Create them through domain modeling when terms or decisions are resolved.

Use glossary terms consistently in code, tests, issues, and proposals. Surface conflicts with existing ADRs explicitly rather than silently overriding them.
